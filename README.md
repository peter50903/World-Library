## #82｜年度報告改用正式 365 日年（待 GPT 審查）

```bash
dotnet run --project src/WorldSimulation.ObserverCli -- --demo --seed 42 --years 8
```

報告第一行寫出曆法來源：「曆法：config/sheets/01_世界參數.csv 的 WORLD_DAYS_PER_YEAR＝365」。文字觀察者在啟動時讀這張正式設定表（整張表先經 Core 的 `ConfigRegistry` 驗證），把一年日數傳給 Core；Core 本身不讀檔、不另寫年長。找不到檔案、該列未啟用、不是 int 或不是正整數都會印出繁體中文原因並以結束碼 2 停止。`--m1-check` 用同一個年界（可用 `--world-params <路徑>` 指定其他 01 表）。

每行年報形如「第 7 年（至第 2555 日）｜週結算 53 次｜…」：第 N 年＝第 (N−1)×365＋1～N×365 日，年界是 365、730、1095……、36500 日，不跳日、不重複。**週結算仍每 7 個世界日一次、跨年不重置**，每次結算歸屬於結算日所在的年份（第 364 日屬第 1 年、第 371 日屬第 2 年），所以每年有 52 或 53 次（365＝52×7＋1，例如第 7 年 53 次）。年度期初／期末讀年界當日的世界狀態；週結算以外的日子不改聚落與資源狀態，所以期初＋週報流量＝期末仍逐年對帳，週結算次數也改用「該年實際應有的次數」檢查，不再假設固定 52 週。

**限制：** 只接入一年日數；月份與二月天數（01 表第 3、5 列）尚未使用。週結算 7 日是既有示範機制，人口、糧食等數值仍是 TEMP。TEMP 存檔可讀日數上限為 36500 日（#90：100 個 365 日年，見 TEMP 待裁決清單 D8），第 100 年末（第 36500 日）的世界可以存讀，第 36501 日起明確拒絕；年界前後存→讀→續跑與直接跑逐日相同（`DemoYearBoundarySaveTests`）。這不是 P1-M0／M1 正式驗收。

## V0-08A｜表 45G M1 驗收報告（TEMP，待 GPT 審查）

```bash
dotnet run --project src/WorldSimulation.ObserverCli -- --m1-check            # 預設：3 種子 × 3 情境 × 100 年
dotnet run --project src/WorldSimulation.ObserverCli -- --m1-check --years 100 --seed 7 --preset frontier
```

文字觀察者以 TEMP 固定種子 **42、7、1** × 既有 TEMP 情境 **一般（normal）、局部饑荒（local-famine，看遷徙）、開拓（frontier，看新聚落）** 各跑 100 年（另可選 `famine` 全面饑荒），逐項列出 `config/sheets/45G_M1驗收.csv` 裡 **Enabled=TRUE** 的檢查。檢查 ID、中文名稱與 Hard／Warning／Behavior Check 分類都從這個 CSV 讀，程式不另存清單；CSV 有啟用、程式沒有量測的項目會顯示「尚未實作」。

**怎麼讀報告：** 每一行是「CheckID｜中文名稱｜分類｜判定｜診斷與證據」，證據會寫出種子、第幾年第幾週（第幾日）、哪個聚落或隊伍。判定：

- **通過（PASS）**：在這次長跑中實際量測到、而且沒有違反。報告重新讀已發布的週報與世界狀態獨立對帳（逐週「上週世界總量＋週報流量＝本週世界狀態」、遷徙隊伍跨週連續且每週只走相鄰格、來源遷出＝出發隊伍、新聚落期初全 0 且全部由開拓隊帶入等），不是只看「程式沒丟例外」。
- **警告（WARN）**：本情境沒有發生可驗證的事（例如一般情境沒有遷徙、沒有開拓），或正式門檻未定案只列數據（`M1_STABILITY`、`M1_VARIETY`），或非 Hard 項目出現違反。
- **失敗（FAIL）**：Hard 項目量測到違反 → 結束碼 1（CI 失敗）。
- **尚未實作（UNIMPLEMENTED）**：例如 `M1_ACCESS` 需要聚落內分組取用，示範聚落仍共用一個糧倉；報告另外列出跨聚落「一處缺糧、另一處有糧」的實例供參考。

**量測限制（TEMP）：** `M1_FAMINE` 只有在「缺糧 → 餓死或外移 → 效果當週實際採收等於舊勞動力上限、下一週實際採收等於降低後的新上限（期初人口 × TEMP 每人每週產量），兩週資源點都仍有剩，且採收確實下降」時才判通過，不從人口前後推斷產能；產量受資源點存量限制而量不到時報警告。`M1_POP` 的出生（示範固定 0）與個體具體化（尚未實作）、`M1_HISTORY` 雖已改用 43F 直接原因編號串接並以週帳核對（#88），但 M1 示範每筆事件至多一個直接原因、完整歷史核心尚未實作，都沒有完整量測，診斷中一律標【覆蓋限制 TEMP】。

最後的總結把所有種子 × 情境合併：任一失敗＝失敗，否則任一通過＝通過。參數錯誤（年數 0、負數、超過 1000、未知情境、找不到 CSV）會印繁體中文錯誤並以結束碼 2 結束。**這份報告只量測、不改任何模擬規則或數值；「沒有 Hard 失敗」不等於 P1-M1 已正式驗收**（種子、情境、穩定與多樣性門檻都是 TEMP，待裁決項目見 #75）。CI 實際執行預設矩陣，檢查 CSV 每個啟用 ID 都出現且總結順序與 CSV 相同。

**工程門檻：** 此項涉及Core資料與亂數，按照Notion03，**須先由Claude於Notion05明確獨立審查接受，才能合併至main**；CI全綠不等於已獲Claude批准。

## V0-02｜Godot 觀察者畫面（第一個真正圖形介面，TEMP 示範）

安裝 **Godot 4.7.2 .NET 版本**及 **.NET 8 SDK**；一般 Godot（沒有 .NET/C# 支援）無法編譯此遊戲。使用 Godot 編輯器選「匯入」，開啟 `godot/project.godot`，點選右上角 **建置（Build）**，接著按 **F6/執行目前場景** 或 **F5/執行專案**。

可在專案根目錄手動先確認 C# 有效：

```bash
dotnet restore godot/WorldSimulation.Godot.csproj
dotnet build godot/WorldSimulation.Godot.csproj --no-restore --configuration Release
```

**預期畫面：** 中央約12×8的彩色2D六角地圖（草地、森林、湖泊；金色圓點僅是示範聚落標記）；右側是世界日期、人口、食物存量、缺糧、抽樣次數及「下一天」「快轉30天」兩個按鈕；下方是該世界實際日結算所產生的事件歷史。畫面開啟時日期為第0日，不會自動流逝；按按鈕會從同一個 `DemoObserverWorld` 真正推進、更新食物與歷史。

**資料可信度界限：** 本畫面、地形、六角座標、示範聚落位置與人口/食物數字均為 `TEMP` 的視覺/數值Fixture，**沒有**載入正式Drive Excel、未產生正式HexCell、RouteSegment、Population或世界生成；六角格相鄰不代表已存在可通行路線。真 `WorldClock`／`Scheduler`／`RngResolutionDraft`／Demo 食物結算與歷史是同一Core執行邏輯；正式AtomicCommit/Save/History Kernel仍待後續階段。Godot C#僅依賴Core；Core不依賴Godot。

**驗收現況：** GitHub Actions除了以 `Godot.NET.Sdk/4.7.2` 編譯C#、執行核心245項測試和文字介面操作，**還會下載並以官方SHA-256校驗 Godot 4.7.2 .NET 引擎，在無畫面模式載入真正場景並觸發「下一天」「快轉30天」按鈕**，查核推進至第31天、產生31筆事件歷史；因而不只是編譯測試。但CI無畫面執行**不代表顏色、中文字型、版面縮放已由真人目視驗收**，仍建議用Godot .NET編輯器開啟場景實際查看。12×8六角格現採 **TEMP 奇數列偏移顯示**，形成近矩形錯列視覺；世界正式座標制度仍未定案。

## 立即試玩：第一個可執行切片（文字介面觀察者 v0）

請先安裝 [.NET 8 開發套件](https://dotnet.microsoft.com/download/dotnet/8.0)，在本程式倉庫的根目錄執行：

```bash
dotnet run --project src/WorldSimulation.ObserverCli -- --demo --seed 42
```

操作：`n` 推進一天；輸入 `1`～`1000` 快轉多天；`s` 查看人口與食物；`h` 查看事件歷史；`q` 離開。觀察與閱讀時，世界時間不會自行前進。

這個切片**真的執行世界排程**：使用世界時鐘（`WorldClock`）與排程器（`Scheduler`）推進時間，〔C05 起每日只推進時鐘；舊的每日資源收穫帳已退役（2026-10-14 使用者裁決），食物生產、消耗與短缺只在多聚落每週結算計算，推進通知與歷史欄改顯示週結算摘要。〕相同的種子、情境與輸入可以重現相同的事件與狀態。

**重要限制：這只是尚未平衡的示範情境**，不是完整的世界生成、人口生死、正式的 M1 經濟、Godot 正式世界地圖、存檔，也不是正式的跨系統原子提交。示範用的人口、食物與消耗數字只是本地示範資料，**不是** 設定檔 `01_世界參數` 的正式值，也不會寫入該表。此切片只示範「世界時間 → 事件 → 變化 → 可讀歷史」的第一條可執行路徑。
