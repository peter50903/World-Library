# 03｜正式提交與事件史

> 前置：第 02 章 a 節已合併。順序 a → b，各一張 PR。行號一律以方法名重定位。

## 共用規則

- 正式狀態只經正式提交更新；同一原子界限驗證並寫入實體／亂數／排程／帳本／歷史；任一寫入或不變量失敗→整包回滾，不得略過歷史或帳本、不得補人口金幣 ID 硬跑（44F Stage 4～6、44E `MOD_COMMIT`、44J `FAIL_CANONICAL_WRITE`、`FAIL_INVARIANT`）。
- 歷史只追加、只接受已提交事件；人口只經出生／死亡／遷徙變更；資源變動要有來源；世界時間單調（40C `INV_TIME_ORDER`、`INV_RESOURCE_CAUSE`、`INV_POP_LEDGER`、`INV_NO_HISTORY_REWRITE`）。
- Godot 沒有寫入權，只送指令、讀檢視（44I `Godot UI`）。
- 不新建跨域交易框架、不另存第二份世界狀態、不加多執行緒。

## b｜正式事件格式與追加式史庫（原 C10）

**玩家看得到：** Godot 事件詳情多 4 行：「類型：EV_DEATH 死亡」（TEMP 類型加【TEMP】）、「地點：(欄,列)」、「相關實體：#3、#57…」、「原因邊：#12（直接）｜根因：資源」。CLI 新指令 `ev N` 印同內容＋直接後果 ID。

**事件類型（Claude 定案，TEMP）：** 出生→正式 `EV_BIRTH`；餓死、途中餓死、自然死亡→正式 `EV_DEATH`（死因放根因與摘要）；24 表尚無的 5 種用 `TEMP_EV_HUNGER`、`TEMP_EV_HUNGER_RECOVERED`、`TEMP_EV_EMIGRATION`、`TEMP_EV_ARRIVAL`、`TEMP_EV_SETTLEMENT_FOUNDED`，放 Core 單一對照表 `DemoEventTypes` 並登記到 TEMP 清單。根因：飢餓類、遷徙類、建村→「資源」；出生、自然死亡→「生命週期」【TEMP】。本節不給重要度、不做 L0～L4 對照（第 13 章）。

**規則：**
- 欄位依 43F：直接原因 1～N 個、只存直接邊；後果由父項反向索引、不另存；相關實體用永久 ID；地點；已提交世界時間；類型；摘要不帶推測；根因不取代實際原因事件。
- 因果邊只有「直接」「促成」兩種，由提交該事件的領域系統寫入；「相關」只是查詢層標記，不得存入史庫。
- 事件 ID 另有序列（不是實體 ID）、不重用；原因不得指向未來或不存在事件。

**實作：**
1. 新資料夾 `src/WorldSimulation.Core/History/`：`enum CauseEdgeKind { Direct = 1, Contributing = 2 }`；`record struct CauseEdge(long ParentEventId, CauseEdgeKind Kind)`；`enum CauseRootCategory`；`record WorldEvent(EventId, WorldTime, EventTypeId, LocationColumn, LocationRow, RelatedEntityIds, Causes, Root, Summary)`，陣列欄位以值比較。
2. `EventHistory`（不可變，內含反向索引）：唯讀 `Count`、`LastEventId`、`Events`、`Find`、`ParentsOf`、`ChildrenOf`；唯一新增方法 `internal AppendCommitted(batch)` 回傳新物件並逐筆驗證：ID＝上一筆＋1、時間不倒退、父 ID 存在且小於自身、不重複、類型已知、相關實體 ID＞0。無任何 public 修改方法。
3. `DemoEventProjection.ToWorldEvents(report, sites, people)`：把聚落事件轉成 `WorldEvent`（同 EventId）；地點＝聚落格，途中餓死＝隊伍當週所在格；相關實體＝聚落（＋隊伍、建村來源聚落）＋當事人；原因＝`CauseEventId>0 ? [Direct] : []`。
4. `DemoHumanLifecycle.Apply`／`Replay` 多回傳 EventId→當事人（新生兒＋母＋父；自然死亡者；本週餓死者），以結構化方式進相關實體；受孕、流產不入史。
5. 唯一寫入：a 節 `StageHistory` 同時呼叫 `AppendCommitted`；`DemoObserverWorld.EventHistory` 唯讀公開；指紋納入史庫。
6. 存檔版本＋1，`State` 加 `History`；讀檔不信任檔內史庫，由週報＋人口重播經同一轉換器重建，重新匯出逐字比對。
7. Godot 詳情與 `VerifyEventDetailSmoke` 輸出加 `Type=TEMP_EV_SETTLEMENT_FOUNDED Edge=Direct`；CLI `ev N`＋冒煙 grep「類型：」。CI 搜尋：`DemoDayEvent` 0 筆；`AppendCommitted` 只出現在史庫與提交物件檔（及測試）。

**驗收：**
- 7 情境 × 種子 {1,2,3,42} 跑 5 年：史庫筆數＝全部週報事件數，逐筆 ID、時間、原因邊一致；`ChildrenOf` 與舊因果索引相同。
- 追加不改寫：跑 N 週記前 k 筆，再跑 M 週後完全相同；沿用 a 節故障矩陣，史庫筆數與指紋不變。
- `AppendCommitted` 反例（指向未來／不存在／自身、跳號、重複、時間倒退、類型空白或未知）全拒且原物件不變；`CauseEdgeKind` 恰兩值；反射檢查無 public 修改方法；查詢 1000 次指紋不變。
- 出生事件相關實體含新生兒＋父母；自然死亡者之後不在人口快照但仍查得到事件。
- 存讀續跑一致；手改 `History` 任一欄→拒讀；上一版檔→「版本太舊」；同種子兩次史庫逐筆相同；守恆照舊；Godot 冒煙通過。

**不做：** 重要度、阿卡西分流、聚合；索引查詢與 Godot 列表改讀史庫（第 13 章）；刪 `DemoCausalIndex`／`DemoEventFilter`／`DemoSettlementEvent`；「促成」邊來源；新增 24 正式列。
