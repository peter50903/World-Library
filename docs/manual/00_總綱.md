## 1｜遊戲是什麼

世界模擬角色扮演遊戲：**世界與歷史是主角**，玩家是介入者，沒有主角特權。
- **第一階段（現在）世界自主演化：** 無玩家也能長期運作、留下可追溯歷史；玩家以觀察者建立世界、快轉、暫停、查詢、讀歷史。
- 第二階段神祇降臨、第三階段人物降臨：第一階段完成門檻全過前不開發（見第 15 章）。
- 技術：Godot 4.7.2 .NET（平面 2D、高解析像素風）＋ C#；模擬核心 `WorldSimulation.Core` 是純 .NET 8 程式庫。

## 2｜手冊怎麼用

1. 章節依開發順序編號；**越前面的章節效力越高**，後面章節與前面衝突時，改後面的。
2. 需要修改已寫好的規則時，不改舊文，而是在被修改章節後面新增**分支章節**（例：`03-1_事件史修正.md`），並在原章開頭加一行「本章部分內容已由 03-1 修正」。
3. 效力順序：**總綱 ＞ 分支章節 ＞ 原章節 ＞ 後續章節**。
4. 尚未開工的章節可以直接改寫內容（還沒有程式依賴它）；開工時若內容只有大綱，先在同一章補齊細節再寫程式。
5. 章節狀態寫在第 9 節目錄；**完成一章只改目錄狀態，不寫工作日誌**。
6. 每章控制在約 3000 字內；超過就拆成 a／b 兩章。

## 4｜不可違反的世界底層法則

1. **實體：** `EntityID` 永久唯一、不重用；名稱只是標籤；進入歷史的實體不硬刪除。
2. **時間：** 單一世界時間、單調前進；365 日／12 月，各月天數同公曆平年（2 月 28 天、無閏年）。存讀檔是遊戲層操作，不是世界內倒流。
3. **守恆：** 金幣、資源、人口只能由真實事件轉移或增減，不得憑空產生或消失；不做隱藏平衡、救濟或補償。
4. **歷史：** 事件是基本單位，只追加、不改寫；重要事件進正式世界史，其餘進觀察者用的阿卡西紀錄。
5. **知識：** 只有「知道／部分知道／不知道」，沒有錯誤知識；角色、國家、神的 AI 只能用自己已知的資訊。觀察者可看真相。
6. **生成：** 程序生成只組合事先設計的定義、模板、特性池，執行期不發明新規則。
7. **AI 角色：** AI 只負責語言、NPC 決策輔助與表現；數值、合法性、資源、事件提交一律由可驗證規則決定。
8. **可重現：** 世界種子＋歷史種子，多條互不干擾的亂數流；同配方＋同操作結果相同。禁止 `System.Random`、自製雜湊亂數。
9. **正式提交：** 改動實體／亂數／排程／帳本／歷史須在同一原子界限驗證與寫入，失敗全部回滾。
10. **存檔：** 目標是正確還原與重現，不以防玩家竄改為需求；只需偵測損毀、版本不符、內部不一致。舊版存檔明確拒讀並提示「版本太舊，請建立新世界」，不寫轉換器。

## 5｜工程硬性規則

- `WorldSimulation.Core` 不得引用 Godot；Godot 只呈現 Core 狀態、送指令，不自行計算世界。
- 文件、留言、玩家可見文字一律繁體中文；英文只限程式識別名稱。
- 正式設定檔唯一來源：`config/世界模擬遊戲設定檔.xlsx`；程式與 AI 只讀 `config/sheets/<分頁>.csv`（只讀需要的分頁與列，欄名對照見 `00B_術語對照.csv`）。改 xlsx 後依序執行 `tools/config_compact.py`、`tools/config_export.py`、`tools/config_refcheck.py`，三者一起提交。
- TEMP 示範數值放 `config/demo/*.json` 或程式常數並標 `TEMP`；正式設定可填暫定值但「說明」開頭標【TEMP】。
- 每張 PR 一件事，數百行內；合併前同一 head 的 CI 必須真正建置、測試並全部通過；不關閉或跳過測試、不強制推送、不刪歷史。
- GitHub Actions 額度有限（2026-10-22）：CI 只在 PR 上跑，同一 PR 新推送會取消舊的，只改文件不跑；百年長測、M1 正式驗收與人口診斷只在 PR 貼「long-run」標籤或手動執行時跑——改到人口、糧食、遷徙規則或章節驗收前才貼。
- 不在未經使用者同意下啟用付費服務；需要 API 金鑰的功能做成「沒有金鑰就不執行」。
- GitHub 只用 `gh api` REST（GraphQL 被擋）。分支命名 `claude/<章號>-<簡述>`。

建置與測試：
```bash
dotnet restore WorldSimulation.sln
dotnet build WorldSimulation.sln --no-restore --configuration Release
dotnet test WorldSimulation.sln --no-build --configuration Release
```
本機沒有 .NET 時以同 head 的 GitHub Actions 結果為準。

## 7｜素材流程（GPT ↔ Claude）

- 清單：`assets/manifest.csv`，每列一個素材。欄位：`ID,檔名,類型,規格,用途,章節,生成方式,狀態,已使用,提示詞`。「檔名」相對於 `godot/assets/`；視覺稿（`UI_MOCK_*`）只是參考，存在 `assets/reference/`，不進 Godot 專案。
- **生成方式**：預設全部 `GPT手動`（使用者 2026-10-15 選擇）；日後若開啟自動生成，才把個別列改成 `自動`。
- **狀態**：`待製作 → 已交付 → 已套用`；不符規格（例如圖內有文字）標 `需重做`，提示詞開頭會註明原因。「已使用」欄打 `V`＝遊戲畫面或音訊目前真的用到。
- **規格**：GPT 交付的原圖由 Claude 裁掉透明邊並縮到「規格」欄尺寸再放進專案；GPT 端尺寸不必精準。
- 程式只經 `godot/Scripts/ArtAssets.cs` 讀素材；任何素材缺少時畫面自動退回純色，不會無法啟動。
- **GPT手動**：使用者把該列「提示詞」整段貼給 ChatGPT（提示詞已含美術基調），下載成品，以「檔名」欄的名字存到 Google Drive 資料夾 **`世界圖書館_素材收件匣`**（資料夾 ID `1MQz1wlDt6fnKDWNHJ2dhXf1e3yFa8zlu`）。Claude 每次開發開始時檢查收件匣，把對得上檔名的檔案處理後放進 `godot/assets/`、狀態改「已交付」，接上畫面後改「已套用」並在「已使用」打 V，在 PR「暫用素材」欄移除該 ID。
- **自動**：GitHub Actions「素材自動生成」讀取 `狀態=待製作` 且 `生成方式=自動` 的列，呼叫 OpenAI 圖片 API 產圖、縮放到規格、提交回 `godot/assets/` 並把狀態改「已交付」。需使用者在 GitHub 設定密鑰 `OPENAI_API_KEY`；未設定時這個工作直接略過。
- 各章「素材需求」段只列 ID 與用途，完整規格與提示詞以 `assets/manifest.csv` 為準。

### 美術基調（每個提示詞都會附上）

平面 2D、高解析像素風（pixel art），中世紀奇幻世界觀但不卡通化；色彩偏自然、低飽和、略帶羊皮紙地圖的溫度；透明背景（PNG）；清楚可辨的輪廓、2 像素以內的描邊；不出現文字、浮水印與任何既有作品的角色或標誌。六角格為**尖頂朝上**（pointy-top）。
