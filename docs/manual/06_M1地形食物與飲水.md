# 06｜M1 地形、自然食物、共享採集與飲水

> 前置：第 03 章 a 節（正式提交）、第 04 章 a 節已合併。對應舊任務 P1.1.01～P1.1.04。
> 本章為「規格＋切片」層級；每個切片開工時先在本章該節補上程式落點，再寫程式。
> 驗收依據：`43C` P1-M1、`45G_M1驗收`（M1_RES、M1_NO_MAGIC_FOOD、M1_POP、M1_STABILITY）。

## 規則（已定案）

**地圖**
- 有限邊界的平面六角格地圖，不環繞；建立世界時可選大小（改變面積，不改單格尺度，不依格數等比例生成人口或國家）。
- 六角格三層呈現：地形底圖＋路徑疊層（道路、河流、水路）＋建築疊層（村莊、城市、城堡）；畫面由世界資料推導，不反過來決定真相。
- 跨格可通行性以 `RouteSegment` 路線段為單一權威；六邊出入口只由路線段衍生；畫面相鄰或線條相交不代表連通；過河必須有橋、渡口或可涉渡段。
- **主水道**是連續佔格的水域格序列；主水道格禁止住宅與聚落。
- **尚無道路時可經「野地」路線段跨格移動**（比道路慢；44D RouteSegment 類型需新增「野地」）。
- 底層用真實路線距離算旅行；介面用角色可知的自然描述（附近、約兩天路程）。
- 地圖檢視：滾輪以游標為錨點縮放、中鍵拖曳、左鍵點格；縮放倍率是 TEMP 顯示參數，不改世界任何狀態。

**自然食物**
- 每種可辨識的自然地形都產非零可採食物；每個來源格每週只有**一份**共享預算，受真實需求、勞力、存量限制，多聚落共享不重複取食。
- 範圍：森林供自身＋六鄰；草原（未開墾、野採）供自身＋六鄰；主水道與一般水域**只供鄰接陸地**、不供自身與第二圈；邊界格只計實際存在者。
- TEMP 量（每來源格每週，示範糧食單位）：森林 20、草原野採 8、主水道 5、一般水域 3。
- 被聚落、城市、道路等人造結構實際佔用的格子不再充當自然來源，但保留底層地形供日後改建。
- 草原野採不是農田；開局沒有農業知識就不產農田糧食（第 08 章）。
- **共享來源不足時，依各聚落成年勞力比例分配**；自然來源未採部分會累積，上限約 4 週供應【TEMP】。

**需求、飲水與飢餓**
- 食物與水必須真實取得與消耗；有糧不等於拿得到；食物會腐敗（全年基準約損耗 50%）。
- 示範食量：每人每週 4 示範糧食單位；**兒童食量為成人一半**【TEMP】。
- **聚落格或鄰格有水域即可取水**，只受取水勞力限制。
- 缺糧形成飢餓債；**餓死者隨機抽取，老幼機率較高**（權重【TEMP】）。不暗中補糧、不救濟。
- 只用人類（RACE_HUMAN）。

## 待定值（Claude 開工時定案並標【TEMP】）

單格公里數、世界尺寸選項、地形移動成本（野地 vs 道路倍率）、交通速度、腐敗週期換算、取水勞力比例、飢餓債轉死亡門檻、老幼餓死權重、分配勞力比例的計算時點。全部進 `config/demo` 或設定檔【TEMP】並登記 TEMP 清單。

## 切片

### a｜地形與路網正式資料（P1.1.01）

> 狀態：完成（2026-10-21）。程式落點（Claude 定案）：`DemoHexCell.MainWaterway`；`DemoHexWorld.Generate` 在 96 次地形後再抽 9 次 GEOGRAPHY：北緣起點 1、每往南一列 1（共 7）、渡口 1，主水道為北緣到南緣連續 8 格；`DemoRouteNetwork`（`DemoRouteSegment`、`DemoRouteKind`：野地／道路／河流／水路／橋／渡口）——相鄰陸地之間野地段、相鄰水道格之間河流段（不供陸路）、渡口連接一個水道格與其全部陸地鄰格（過河唯一陸路）、一般水域無陸路；成本與單格尺度在 `config/demo/map-routes-temp.json`【TEMP】。遷徙、開拓選址與讀檔路線檢查都只沿陸路路線段；點格查詢多一行「路線：…」；Godot 主水道依 Core 旗標畫河流、渡口畫褐色環與虛線。世界尺寸仍固定 12×8（尺寸選項待世界建立介面時做）。地圖改變使各種子的示範結果改變；依規則不調數值補回。
- Core 機讀六角格：座標（尖頂、偏移＋軸向）、地形、主水道旗標、人造佔格。
- `RouteSegment`：兩格、類型（野地／道路／河流／水路／橋／渡口）、通行成本；六邊出入口由路線段衍生。
- 世界生成以世界亂數流產生地形、主水道（連續序列）、野地路線段；同種子可重現。
- Godot 地形改讀 Core；點格顯示路線段與出入口。
- 驗收：兩格相鄰但無路線段→不可通行；過河無橋渡→不可通行；同種子地圖逐格相同；主水道格無聚落。

### b｜自然來源型別與鄰接取用（P1.1.02）
- 來源型別：森林、草原野採、主水道、一般水域；可及範圍規則如上；人造佔格排除。
- 舊 `DemoForagingWorld`／`DemoHexFoodCatchment` 正式化，量從 `config/demo` 讀。
- 驗收：邊界格、主水道自身、第二圈、被佔格各一則反例。

### c｜來源存量、累積與勞力比例分配（P1.1.03）
- 每來源持久存量：每週再生＝預算；未採部分累積，上限 4 週【TEMP】；採收從存量扣。
- 分配：同一來源依各聚落**成年勞力比例**分配，取整餘數以聚落 ID 遞增分配（可重現）；每聚落不超過需求與勞力上限。
- 沿用第 04 章 c 節的來源帳，帳上加期初存量／再生／採收／期末存量。
- 驗收：兩聚落共用一森林時不出現「可避免的餓死」（同樣總量下比例分配的餓死數 ≤ 貪婪分配）；Σ採收 ≤ Σ存量；百年守恆。

### d｜飲水、食量與飢餓死亡（P1.1.04）
- 每聚落每週取水：聚落格或鄰格有水域才可取，需取水勞力；無水或勞力不足→脫水債（29 `P_WATER_DEHYDRATION_RATE` 為【TEMP】）。
- 兒童半份食量；成年勞力與未成年分離；腐敗損耗套用。
- 餓死名單：以 POP 亂數依年齡權重抽取（沿用第 04 章 a 節的抽樣協定，新動作代碼）。
- Godot 糧食診斷加「水：可取／不足」與老幼餓死分類。
- 驗收：遠離水源的聚落出現脫水反例；兒童食量正確；餓死抽樣同配方可重現；M1_NO_MAGIC_FOOD 通過。
