## 2｜量測方法（09-1）

- CI 用 Godot 無頭模式跑 `WORLD_SIM_PERF_SMOKE=1`：大地圖（72×48）、人類繁衍世界、種子 7、跑五年。
  量下面每一項，印成一行 `WORLD_SIM_PERF:`。
- 只印數字、不設門檻。
- **同一份程式在不同 CI 機器上會差 ±20%**（核心每週 24～32 毫秒，核心沒改過）。
  所以下面只把差距明顯大於這個範圍的列為改善。

| 項目 | 意思 |
|---|---|
| CoreWeekMs | 核心每週結算（背景執行緒） |
| RefreshMs | 面板與地圖資料完整更新一次 |
| LightDayMs | 播放時，同一週裡的每日更新 |
| SurfaceFullMs | 地表整張重建（開局、讀檔、換地圖） |
| BakeChunkMs | 烤一塊 256×256 地表（拖曳、縮放時逐塊烤） |
| LayoutMs／WeekLayoutMs | 聚落版面：第一次／之後每週 |

## 3｜移除多餘的程式與素材（09-2）

- **程式**：
  - 3D 等角原型、2D 等角原型（工具列的「3D」「等角」按鈕）。
  - 小人走動。
  - 動物、怪物的動畫。
  - 第四到第八批與 KayKit 的舊建築畫法、舊聚落外觀。
  - 第五到第八批素材的匯入工具。
- **素材**：
  - `kaykit/`、`iso/`、`sprites/`、`textures/`。
  - `px2/` 的 `b8_*`、`kk_*`、`bld_*`（篝火與囤糧除外）、`unit_*`、`ani_*`、`mon_*`、`fx_bubble_*`。

## 4｜參考資料與採用的做法（09-3）

| 來源 | 重點 | 採用 |
|---|---|---|
| Godot 文件〈CPU optimization〉 | 先量測找瓶頸，再優化；C# 注意垃圾回收；可平行的計算用多執行緒 | 先做量測（第 2 節），只改量到的瓶頸；地表計算平行化 |
| Godot 文件〈Thread-safe APIs〉 | 場景樹不是執行緒安全；不要在其他執行緒改 Image 或貼圖 | 平行的只有「算顏色寫進 byte 陣列」；建立、更新貼圖照舊在主執行緒 |
| Godot 論壇〈Chunking system causing stutters〉 | 一次生成大量區塊會卡；工作移到背景或分散到多幀 | 地表本來就分幀烤；這次把每塊的計算平行化，一塊從約 25 毫秒降到 5～10 毫秒 |
| Godot 論壇〈Why does drawing many circles tank the fps〉 | 畫面成本在繪圖指令數；改用貼圖、能批次的指令 | 拿掉小人、動物、怪物的逐一繪製（09-2） |
| Godot 論壇〈Large 2D tilemap…〉、〈Very large TileMapLayer〉 | 很大的 TileMapLayer 改格子會卡 4～5 毫秒；大地圖要分區 | 不改用 TileMapLayer；維持「分塊烤圖＋快取」，只重烤變動的塊 |

## 5｜優化項目（09-3）

1. **地表逐列平行計算**：
   - 烤一塊與整張縮圖時，每列的地面顏色交給多個核心同時算。Ground 只讀已建好的表；延後建立的表先在主執行緒建好。
   - 樹、山頭等零件，以及上傳貼圖，仍在主執行緒依序做。
2. **同一週只更新日期與時間控制**：
   - 世界狀態只在每週結算時改變，所以播放時同一週的其他六天不重建清單、字典與文字。
3. **蓋好的聚落版面沿用**：
   - 聚落的輸入（等級、人口、信仰、前面聚落的用地…）沒變、也沒有工地時，這一週直接用上次的版面。
4. **右側聚落清單重用列**：
   - 每週依人口重排，列依位置重用，只改文字、色塊與記在列上的聚落編號，不再整個重建。

## 6｜結果

（大地圖 72×48、81 個聚落、1,622 人；取核心每週時間相近的兩次 CI 比較）

| 項目 | 優化前 | 優化後 | 改善 |
|---|---|---|---|
| 地表整張重建（開局、讀檔） | 1,878 ms | 819 ms | **−56%** |
| 烤一塊地表（拖曳、縮放） | 25.6 ms | 9.4 ms | **−63%**（約 2.7 倍） |
| 聚落版面，每週 | 32.5 ms | 4.9 ms | **−85%** |
| 播放時每日更新（同一週） | 34.7 ms | 0.03 ms | **約 1,000 倍**（一週七天裡六天） |
| 聚落版面，第一次 | 282 ms | 214 ms | −24%（接近機器誤差） |
| 核心每週結算 | 31.7 ms | 29.5 ms | 不變（在誤差內，這次沒有改核心） |

**體感上的意思**（60 幀＝每幀 16.7 毫秒）：

- **拖曳、縮放**：以前烤一塊就超過一幀（25 毫秒），畫面一移動就頓；現在一幀可以烤 1～2 塊。
- **播放**：每週結算時的版面更新從約 2 幀降到不到 1 幀；一週裡其他六天幾乎沒有成本。
- **開局、讀檔、換地圖**：等待從約 1.9 秒降到約 0.8 秒。

## 7｜還沒解決、下一步

- **每週一次的完整面板更新**還要約 30 毫秒，是一次頓一下的主要來源。
  - 其中「面板」段（圖例、通知、追蹤、清單、編年史、年表）約 20 毫秒。
  - 下一步：沒開的面板不算；文字只在內容改變時才重設。
- **核心每週結算約 25～30 毫秒**：
  - 在背景執行緒跑，不卡畫面，但限制了最高速度（每秒約 35 週）。
  - 每週配置約 9.7 MB 記憶體，下一步可以重用暫存。
- **遠景地表**仍是縮圖。可以考慮半解析度的中距離圖層。
