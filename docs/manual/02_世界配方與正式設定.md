# 02｜世界配方與正式設定

> 前置：PR #128（點格查詢）、#130（亂數用途校正，存檔第 4 版）已合併。
> 兩節各開一張 PR，順序 a → b。行號會變，一律以類別／方法名定位。

## 共用規則

- 世界種子與歷史種子分開；歷史種子可由玩家輸入或由世界種子衍生；同世界可搭不同歷史種子產生不同歷史（41A `SEED_WORLD`、`SEED_HISTORY`）。
- 世界配方＝規則版本＋設定雜湊＋程式版本＋世界種子＋歷史種子（40F `VER_WORLD_RECIPE`；`VER_CODE`＝Git 提交雜湊）。
- **參數單一權威：** `01_世界參數` 放世界結構常數、硬性規則與開關；`29_數值參數` 放可調且有上下限的數值；同一語義的生效值只能有一份，其他地方只引用 ParameterID。
- 29 的生效值＝「預設值」欄，必須在最小值～最大值之間；「是否已平衡＝FALSE」或說明開頭【TEMP】一律視為暫定（照用、標示暫定）。
- Core 不直接讀檔：設定文字編入組件或由宿主提供，Core 只解析、驗證、算雜湊；載入後不可變。
- 存檔格式改變就把版本常數＋1（不寫死數字）；舊版走既有單一拒讀路徑。

## a｜世界配方與建立指令（原 C06）

**玩家看得到：**
- 控制台情境下拉下方：「世界種子」「歷史種子（留空＝由世界種子衍生）」兩個輸入框＋「以此種子建立世界」按鈕；已推進的世界須先確認（沿用情境切換的確認列）。
- 狀態欄顯示完整配方：世界種子、歷史種子（自訂／衍生）、規則版本【TEMP】、設定雜湊（b 節完成前顯示【TEMP 佔位】）、程式版本。
- CLI：啟動參數 `--history-seed N`；互動指令 `new <世界> [歷史]`（已推進時要再輸入 `yes`）；`s` 多印「世界配方｜…」。

**實作：**
1. Core 新增 `World/WorldRecipe.cs`：`record WorldRecipe(ulong WorldSeed, ulong? HistorySeedInput, string RulesVersion, string ConfigHash, string CodeVersion)`；屬性 `HistorySeed`（輸入或 `SeedDerivation.HistorySeed(WorldSeed)`）、`HistorySeedDerived`、`ConfigHashIsTemp`；`ForSeeds(world, history?)`；`Describe()` 一行繁中（Godot／CLI 共用）。TEMP 常數：規則版本 `TEMP-RULES-0`、設定雜湊佔位 `TEMP-CONFIG-HASH-PENDING`。
2. 程式版本取 Core 組件 `AssemblyInformationalVersionAttribute` 的 `+` 後雜湊；取不到顯示「未知（本機建置）」，不得編造。先在 CI 實測。
3. `DemoObserverWorld(WorldRecipe, DemoWeeklyTempConfig)` 以 `RngRegistry.Create(recipe.WorldSeed, recipe.HistorySeedInput)` 建立；舊 `DemoScenario` 建構子轉呼 `ForSeeds(scenario.Seed)`；C05 的 internal 歷史種子參數改走配方後刪除；公開唯讀 `Recipe`。約 95 處 `DemoScenario.Sample` 保留不改。
4. 存檔：版本＋1；檔頭 `Scenario` 改 `Recipe`（五欄）。讀檔以檔內配方重建；規則版本不符拒讀；程式版本與設定雜湊只記錄不比對（比對在第 04 章 b 節）。重新匯出比對時程式版本以檔內值為準。
5. Godot：非 0～18446744073709551615 的整數→通知「種子必須是 0～18446744073709551615 的整數，世界未改變」；第 0 日直接建立，否則顯示確認列；原「開始新的 TEMP 示範」照舊。
6. 冒煙：Godot `WORLD_SIM_RECIPE_OK: World=123 History=456 SameRecipe=1 HistoryOnlyMapSame=1 BadSeedRejected=1 ConfirmRequired=1 SlotsUnchanged=1`（經真實輸入框與按鈕訊號）；CLI 冒煙加 `--history-seed 7` 與 `new 5 6`，grep「世界配方｜世界種子 5｜歷史種子 6」。

**驗收：**
- 同配方兩次建立指紋相同，各跑 2 年仍相同；世界種子 1～10 至少一組地圖或聚落不同。
- 同世界種子、歷史種子 456 vs 789：地圖、聚落、人口群體、世界流狀態完全相同；歷史流狀態與指紋不同（人口亂數接上前出生死亡事件相同是預期，不得造假差異）。
- 歷史種子留空＝與 `DemoScenario.Sample(seed)` 指紋相同。
- 自訂歷史種子世界存→讀→續跑與未中斷逐事件相同；手改 `Recipe` 的歷史種子或規則版本→拒讀、世界不變；上一版存檔→「版本太舊，請建立新世界」。
- 輸入 `abc`、`-1`、超出範圍、未確認、取消→世界與存檔槽位元組不變。

**不做：** 正式設定雜湊（b 節）、存檔清單／校驗碼（第 04 章）、世界大小與初始文明程度、覆寫時間線、人口亂數。

## b｜正式設定讀取與設定雜湊（原 C11）

**玩家看得到：** 狀態欄與 CLI（互動開場、無畫面長測第一行、`s`）顯示一行：
「正式設定：01 已載入 N 列｜29 已載入 M 列（暫定 K：未平衡 U、【TEMP】T）｜設定雜湊 前16碼｜TEMP 設定雜湊 前16碼」。
01 或 29 有任一不合法列→Godot 不建立世界並顯示「正式設定讀取失敗：第 R 列 ID：原因（共 E 處）」；CLI 印同句、結束碼 2。CLI 開場「尚未載入試算表的正式世界設定」那句刪除。

**實作：**
1. Core csproj 編入資源：`config/sheets/*.csv` → LogicalName `WorldSimulation.ConfigSheets/<檔名>`；`config/demo/*` → `WorldSimulation.ConfigDemo/<檔名>`；`DemoForagingWorld.LoadSettings` 改讀新名稱，刪舊名稱。
2. `Config/TunableParameterRow.cs`、`TunableParameterSheet.Parse`（依欄名取欄，沿用 `ParameterSheet` 的 CSV 切欄，不寫第三份）、`TunableParameterRegistry.ValidateAndCreate`：空白停用列比照 `ConfigRegistry`；啟用列需 ID、預設／最小／最大皆可解析（InvariantCulture；bool 只收 0／1）、最小≤預設≤最大、是否已平衡為 TRUE/FALSE；提供 `GetInt`／`GetNumber`／`GetBool`、`IsProvisional`、各計數。錯誤沿用 `ConfigError`、繁中原因。
3. `Config/ConfigHash.Compute(files)`：SHA-256；檔名依 Ordinal 排序；每檔寫入 UTF8(檔名)、0x00、UInt64LE(正規化長度)、正規化內容（去 BOM、CRLF→LF）；輸出 64 個小寫十六進位字元。設定雜湊涵蓋 `config/sheets` 全部 CSV；TEMP 設定雜湊涵蓋 `config/demo` 全部檔案（C# 內寫死的 TEMP 情境不在內，畫面註明）。
4. `Config/OfficialConfig.Load()`：取全部資源→算兩個雜湊→驗 01、29→檢查 01／29 ID 不重複；成功回傳 `World`、`Tunable`、`ConfigHash`、`TempConfigHash`、`SheetCount`、`Describe()`；失敗列出全部錯誤（含分頁名）。`Lazy` 單例；另留 internal 注入版本供測試。
5. CLI 與 Godot 改用同一載入器；`WorldCalendarConfig.LoadDefault()` 與 Godot `WorldCalendarFile` 改由 `OfficialConfig.World` 建曆法（`--world-params` 外部檔保留給錯誤測試）。
6. a 節已合併：`WorldRecipe.ForSeeds` 設定雜湊改填實際值、`ConfigHashIsTemp=false`、刪佔位常數；**不升存檔版本**。
7. 冒煙：Godot `WORLD_SIM_CONFIG_OK: Sheets=<數> Hash16=<前16碼>`；CLI grep「正式設定：01 已載入」；CI 加一步比對 Godot 與 CLI 的 Hash16 相同。

**驗收：**
- 真實資源載入成功；`SheetCount`＝磁碟 CSV 數；01 列數、29 啟用數、未平衡數、【TEMP】數與測試內以 C# 重算真檔的結果相同（不寫死）；`IsProvisional("P_WATER_DEHYDRATION_RATE")`＝true。
- 磁碟自算雜湊＝資源雜湊；CRLF／BOM／檔案順序不影響；改任一 CSV 一字（含停用列、非參數表）→設定雜湊變、TEMP 不變；改 demo JSON→只 TEMP 雜湊變；增刪 CSV→改變。
- 反例各一（錯誤含分頁、列、ID）：超出上下限、最小＞最大、29 內重複、29 與 01 重複、型別 `float`、bool 預設 `2`、是否已平衡空白、缺預設值。
- 同種子跑 2 年，本節前後指紋逐週相同（不接線任何 29 值）。
- 存檔格式不變；既有存讀、重播、設定同步 CI 照舊。

**不做：** 把 29 參數接進示範世界（由各消費章節按 ID 接）、存檔比對雜湊、事件校驗碼、改 xlsx／CSV／demo 內容、解析其他分頁、搬移重複參數。
