# 14-1｜底層法則稽核與修正（分支章節）

> 使用者 2026-11-16：稽核 `WorldSimulation.Core` 是否違反總綱第 4 節（世界底層法則）與第 5 節（工程規則），
> 列出清單後一項一項修；只有規則面（概念）的才問使用者。
> 本章是清單與進度；每一項一張 PR，做完一項才開下一項。

## 1｜稽核結果

- 沒有問題：Core 沒有引用 Godot；沒有 `System.Random`、時間或 GUID 進規則；史庫只追加；實體編號只遞增不重用；
  會影響結果的迴圈都有明確排序；週結算的糧食、人口、飢餓債都有對帳（下面第 3 項除外）。
- 稽核方式：亂數、實體、史庫、提交物件、世界主類別、週結算、生死、群體人口、天災、怪物、糧稅、重播驗證逐行讀；
  知識樹、文化、信仰、開墾、遷徙路線、採集分配、勢力範圍、環境、存讀檔匯入只做關鍵字掃描（之後修到時再逐行讀）。

## 3｜概念三項（使用者 2026-11-16：綜合現實常識與遊戲性由 Claude 決定）

### ★4 已知資訊：估算別人的兵力只知道舊消息（存檔第 61 版）

- 現實：國王靠商旅與探子知道鄰國的虛實，越遠越舊；自己人的兵力是清楚的。遊戲性：偶爾會有誤判的戰爭與通牒，歷史比較有戲。
- 規則：相距 d 格的聚落，只知道對方「d × 每格延遲週數」之前那一週的期末人口（與缺糧遷徙的消息同一個延遲設定，目前每格 1 週）。
  - 王國宣戰：對方的兵力用國王所知的人口估；己方用真實值。
  - 派系下通牒、逼宮：上級的兵力用派系首領所知的人口估；派系自己用真實值。
  - 戰爭與鎮壓實際開打之後的傷亡照真實人口算。
- 不改的兩處（寫成明文規則）：
  - 婚嫁：12 格內親友往來頻繁，哪個村有未婚的人視為已知。
  - 開拓選址：開拓隊出發前會派人勘查，搜尋範圍內土地的餘量與怪物地盤視為親眼看過。

### ★6 至少留一人：保留，寫成明文規則「倖存者」

- 現實：天災、獸襲、襲擊與攻城很少殺到一個不剩，總有人逃出來。遊戲性：使用者 2026-11-11 回饋過「村子不停滅亡」，
  拿掉會讓小村更容易消失；聚落真正的消亡仍然會發生——餓死、老死、人口外移後成為遺跡。
- 規則：天災、怪物襲擊與討伐、戰爭、野獸襲擊造成的死亡，最多殺到該聚落（或隊伍）剩一人。飢餓與老死不受此限。
- 這是公開的規則，不是隱藏救濟；事件記的死亡人數就是實際死亡人數。

### ★9 狩獵：維持現在的做法，寫成明文規則

- 現在的關係：聚落每年從採集範圍取走獵物；獵物豐富時，獵場來源才有供應加成。獵過頭、獵物變少，加成就消失。
  所以糧食的多寡已經跟著獵物走，只是不逐隻換算。
- 不改成「一隻獵物換幾份糧食」入帳：那要新增來源種類與整套來源帳，換來的差別玩家看不到（第 08-16 章：表現優先、看不到的不做細）。
- 規則：獵物是獵場加成的條件，不另記糧食帳；獵物數量的增減照野生動物年結算。

## 4｜各項細節

### 第 3 項：隊伍遺留糧食（完成）

- `DemoMigrationWeekLedger.FoodAbandoned`：隊伍全員死亡那一週，剩下的糧食記在這一欄，期末糧食歸 0。
  - 全員老死（生死步驟）：自然死亡事件後面加「隊伍全員死亡，攜帶的糧食 N 遺留在途中」。
  - 全員餓死（週結算）：同樣記帳；實務上餓死的隊伍糧食已經是 0。
- 對帳：`期初－消耗－遺留＝期末`；還有人活著不得遺留；全員死亡期末必為 0。不變量、M1 驗收與讀檔重算共用這條。
- 遺留的糧食不再回到世界（沒有人撿）；之後要做「拾荒」再從這一欄接。

### 第 1 項：世界法則切換紀錄（完成）

- `DemoObserverWorld.LawChanges`：每次切換記「第幾週結算之後改成什麼」，只追加。同一週改幾次只留最後一次，改回原樣就當沒改。
- 存檔多一欄 `LawChanges`；讀檔檢查週次遞增、不超過已提交週數、最後一筆等於目前的法則。
- 重播驗證在同一週套用，關過法則的存檔也驗得過。
- 加這一欄之前、法則不是全開的舊存檔：讀得進來，但當成「現在才切換」，重播驗證仍然不會過（本來就不會過）。
- 切換紀錄目前只在存檔與指紋裡，還沒顯示在編年史；要顯示時從這份紀錄接。

### 第 5、11 項：亂數抽樣鍵不撞號（完成，存檔第 60 版）

原則：**原本不會撞的範圍一律照舊**（既有種子的世界不變），只有會撞的範圍改用新的鍵。

| 位置 | 原本會撞的情況 | 現在 |
|---|---|---|
| 勢力（忠誠、戰爭） | 聚落編號 ≥ 131072（編號是全世界共用的流水號，大地圖長跑會到） | 用聚落自己的編號當鍵 |
| 怪物 | 第 256 個以後的地下城 | 用地下城序號當鍵 |
| 地下城取名 | 重試到第 22 次以後，用到下一年「是否出現地下城」的抽樣 | 另一個命名空間 |
| 天災 | 目前用到的位置剛好沒撞；其他位置會撞 | 其他位置另一個命名空間 |
| 年齡群 | 出生年在 −2048～2047 以外，撞到下一個聚落 | 放到另一段鍵 |
| 代表人物老死 | 實體編號 ≥ 8193 時可能等於某個年齡群的鍵，兩者抽到同一個數 | 編號 ≥ 8193 的改用自己的動作碼 |

- 只有最後一列會改變一般世界的結果（代表人物編號超過 8193 之後的老死時間），所以存檔改第 60 版。
- 隕石礦脈的字典遍歷加上排序（第 11 項；目前每年最多一顆，結果不變）。

### 第 2 項：各平台相同的次方與對數（完成）

- 新檔 `DemoDeterministicMath`：`PowInt`（整數次方）、`Log`、`Exp`、`Pow`，只用加減乘除、取整與二的次方縮放。
  這些基本運算（以及原本就在用的開根號）在每個平台結果相同；作業系統數學函式庫的 `Pow`、`Log` 不保證。
- 用在：每週受孕、流產、老死機率（年或月機率換成週機率）、二項抽樣的起始機率、常態近似的反函數。
- 與原本的數值差在第 15 位以後，抽樣結果實際上不變，所以沒有改清單原先寫的「全部改整數」，存檔也不改版。
- Core 的規則裡不再有 `Math.Pow`、`Math.Log`、`Math.Exp`；之後新增規則要用時一律走這個檔。

### 第 7 項：人物登記表（完成）

- `DemoObserverWorld.PersonRecord(編號)`／`PersonRecords`：每位代表人物上任時登記（姓名、性別、出生年、職務、聚落、上任週），
  卸任時補上卸任週與原因；之後不更動、不刪除。與當週歷史在同一次提交寫入。
- 每週對一次：登記表上「在任」的人一定等於目前在任的代表人物（沒有卸任紀錄就離開名單的，當週補上「卸任」）。
- 存檔多一欄 `People`；讀檔檢查編號唯一、週次合理、在任名單一致。沒有這一欄的存檔只登記目前在任的人。
- 存檔會變大：大地圖百年約多幾 MB（每人一筆，約 150 位元組）。
- 還沒接到畫面：人物頁目前只開得了在任的人；要讓已故人物也能開，從這份登記表接（另開工作）。
- 沒做的部分與理由：
  - 遷徙隊伍抵達後不登記：隊伍是無名的群體（第 07-1 章：大多數人只是統計數字），數量極多，事件裡已有編號與起訖。
  - 文化、信仰、地下城、戰爭仍用各自的編號：文化與信仰的編號同時是亂數鍵，換成共用編號會讓所有種子的世界重來；
    它們從不刪除，所以不會重用。之後新增的實體類型一律從共用分配器取號。

### 第 8 項：壓縮在提交界限外（記錄，不修）

- `CompactIfDue` 在發布之後執行，內容全部由已發布的資料推得，先算好年帳與較早事件才指派四個欄位。
- 礦脈、地下城、勢力、怪物的快取同樣只由已發布資料推得；它們不是執行緒安全的，靠 Godot 端「背景推進時主執行緒不碰世界」的約定。
