# 04｜人口亂數與存檔驗證

> 前置：a 節只需 PR #130 已合併；b 節需第 02 章 a、b 與本章 a 已合併；c 節需 b 已合併。各一張 PR。

## 共用規則

- 存檔目標是正確還原與重現；只偵測損毀、版本不符、內部不一致。**不以防玩家竄改為需求**：完整重播驗證只做選用工具，讀檔預設不跑（`ReplayVerifyOnLoad=false`）。
- 程式版本不符只警告、不拒讀；規則版本或設定雜湊不符拒讀並說明。
- 讀檔通過驗證才取代目前世界；失敗時目前世界與檔案位元組不動。世界狀態直接恢復，不可只靠重播才能讀檔（44H `SAVE_WORLD`、`SAVE_TX`、`SAVE_PLAYER_POLICY`）。
- 每節改格式都把存檔版本常數＋1；上一版一律「版本太舊，請建立新世界」。
- 本章**不改任何生死規則、分配規則或 TEMP 數值**。

## a｜人口生死改走正式亂數協定（原 C12a）

> 狀態：完成（2026-10-21）。存檔第 7 版。固定向量（世界 42、衍生歷史、人 1、週 1、受孕）原始值＝11404040931146213669。`DemoPopulationDraws` 內快取每人的局部亂數物件（只省 SHA-256 計算，結果仍為純函式）。

**看得到：** 「人類繁衍」情境的受孕、流產、新生兒性別、自然死亡改由歷史種子的 POP 流決定：同世界種子、不同歷史種子→地圖與初始人口相同、出生死亡不同；兩種子皆同→逐事件相同。程式內不再有第二套亂數。

**規則：** `POP`＝雜湊(歷史種子, 'POP')；個人抽樣用實體局部索引亂數 v1（純函式、與處理順序無關、不推進十條全域流計數器、實體 ID＞0）；禁止另建亂數產生器（41A `SEED_POP`、`SEED_ENTITY_LOCAL`、`RNG_ENTITY_LOCAL_V1`；44E `MOD_RNG`）。

**實作：**
1. 新增 `World/Demo/DemoPopulationDraws.cs`：建構子取 `RngRegistry`；`bool Hit(long personId, int week, DemoPopulationAction action, double chance)`＝`EntityLocalRandom.Create(registry, EntityId.From(personId), RngStreams.Pop, "TEMP-HUMAN-DEMOGRAPHY-v1").GetUInt64(week*8+action)`（NaturalDeath=1、NewbornSex=2、Miscarriage=3、Conception=4）。機率用整數門檻：`chance<=0`→false、`>=1`→true，否則 `(draw>>11) < floor(chance*2^53)`。
2. `DemoTempDemography` 刪 `Seed` 與 `Roll`；`Open` 不收種子；`AdvanceWeek` 收 `draws`；新生兒性別用已發出的新生兒 ID 抽；快照刪 `Seed`。
3. 世界週結算傳 `new DemoPopulationDraws(_rng)`；`DemoHumanLifecycle.Apply`／`Replay` 加 `draws`；讀檔用候選世界恢復的 `_rng`。
4. 存檔版本＋1。CI 加搜尋：`0x9E3779B97F4A7C15|0xBF58476D1CE4E5B9|new Random|Random\.Shared` 在 `src`、`godot/Scripts`（排除 `Core/Rng/`）必須 0 筆。
5. Godot「有出生」冒煙種子若改變，換種子或用既有搜尋方式，**不得調數值**。

**驗收：**
- 同世界種子、歷史種子 A／B（5 組）跑 10 年：地圖、聚落、開局名冊相同；生死事件至少一組不同。同配方逐週事件與指紋相同。
- 同（人、週、動作）不同順序、重複 1000 次結果不變；`RngRegistry.Capture()` 前後相同。固定向量（世界 42、衍生歷史、人 1、週 1、動作 4）的原始值寫進測試。
- `DemoTempDemographyRules` 對 0～120 歲輸出前後相同；既有生育／死亡測試只改建構方式、不放寬斷言。
- 故障注入、守恆、存讀續跑、偽造出生被拒照舊；Godot `WORLD_SIM_HUMAN_OK` 通過。

**不做：** 改死亡率、混齡開局、穩定配對（第 07 章）；重開遷徙；改 `EntityLocalRandom` 協定。

## b｜存檔標頭、相容性檢查與選用完整驗證（原 C12b）

> 狀態：完成（2026-10-21）。存檔第 8 版。實作備註（Claude 定案）：標頭另檢查「標頭欄位＝標頭內配方」（不一致即拒讀）；校驗碼取檔內 `State` 原文（匯出時先單獨序列化再原文嵌入）；存檔槽檔頭讀得出但②～⑧不符時顯示「不相容（原因）」，連版本或標頭都讀不出時維持「無法辨識（原因）」；程式版本不同時讀檔成功並在通知列／CLI 顯示警告。

**看得到：** 存檔多一個標頭；讀檔先驗標頭，不符就以繁中說明哪一項不符（含存檔值與目前值）。Godot 存檔槽與 CLI `slots` 每槽顯示「槽 N：第 D 日｜世界種子 W｜歷史種子 H｜情境｜設定 前8碼｜存檔第 V 版｜可讀」或「…｜不相容（原因）」。新增「完整驗證」：CLI `verify N`、Godot 每槽一個按鈕，從第 0 日重跑到存檔日逐週比對，報第一個分歧週與欄位。

**實作：**
1. `World/DemoSaveManifest.cs`：`record DemoSaveManifest(StructureVersion, RulesVersion, ConfigHash, TempConfigHash, CodeVersion, WorldTimeTicks, Recipe, StateChecksum)`；結構版本＝存檔版本常數。
2. 校驗碼＝SHA-256(`State` 節點無縮排序列化)。頂層只留 `Version`、`Manifest`、`WeeklyConfig`、`State`（配方移入標頭）。
3. 讀檔順序（任一失敗即拒）：①版本（舊版走單一拒讀）②標頭結構版本＝`Version` ③規則版本 ④設定雜湊「正式設定不符」⑤TEMP 設定雜湊「TEMP 示範設定（config/demo）不符」⑥程式版本→**只警告**（通知列顯示，不拒讀）⑦世界時間＝`DaysElapsed` ⑧重算校驗碼「存檔內容損毀（校驗碼不符）」⑨既有結構驗證與重新匯出比對（一項都不刪）。
4. `VerifyTempSaveByReplay(json)`：先跑 ①～⑧，再以標頭配方逐日重跑、逐週比對週報、最後全檔比對；回傳 `record DemoReplayVerification(Ok, FirstDivergentWeek, FirstDifference, Elapsed)`，差異寫到「第 W 週 聚落 X 的 Harvested：存檔 120，重算 20」層級。
5. `DemoSaveSlots.ReadHeader` 做 ①～⑧；`DemoSaveSlotInfo` 加 `Recipe`、`Compatible`、`IncompatibleReason`。
6. CI：新版號與 `Describe()` 格式；CLI 冒煙加 `verify 2` grep「完整驗證槽 2：一致」；Godot 冒煙 `WORLD_SIM_SAVE_HEADER_OK: Compatible=1 ConfigMismatchRejected=1 ReplayVerified=1`。

**驗收：**
- 各情境 × 種子 1～5 × 存點（0、7、9、365、730 日）存讀續跑一致、完整驗證全 Ok。
- 反例（拒讀、訊息含指定字樣、世界與檔案不變）：截斷一半、`State` 改數字未改校驗碼、設定雜湊、TEMP 雜湊、規則版本、結構版本不符、上一版檔。程式版本不符→可讀並出現警告。
- 重播偵測：重算校驗碼後，共享採集某週採收 +100 並修正期初期末、人類繁衍某週餓死 −1 並修正→`VerifyTempSaveByReplay` 回報 Ok=false 且分歧週正確。
- 同配方兩次匯出位元組相同；PR 說明附 100 年存檔讀檔與完整驗證耗時。

**不做：** 事件校驗碼、N 年比對指令、存檔 ID／建立時間、來源帳（c 節）。

## c｜共享採集來源層級週帳（原 C12c）

**看得到：** 共享採集情境每份週報多一份來源帳（每來源本週預算、分給哪些聚落各多少、未採多少）；讀檔逐週檢查內部一致；Godot 糧食診斷「來源→採收」讀已提交的來源帳並顯示「（預算 A，未採 U）」。

**實作：**
1. `record DemoSourceWeekLedger(Week, SourceId, Kind, Column, Row, FoodAvailable, Shares, Unharvested)`、`record DemoSourceShare(SettlementId, Food)`；`DemoWeekReport.Sources`（非共享情境為空）；依 SourceId、SettlementId 遞增排序；預算＞0 的來源都列。
2. `Settle` 在共享分配後組出來源帳；`Regenerated` 欄在共享模式改註解為「由來源帳轉入」。
3. `Verify`：每源 Σ份額＋未採＝預算、皆非負、同源不重複聚落；共享模式每聚落 `Harvested`＝`Regenerated`＝Σ份額；非共享模式來源帳為空。
4. 讀檔加 `CheckSourceLedgers`：來源清單＝依地圖與當週聚落重算；份額聚落在可及範圍；每聚落合計 ≤ 需求且 ≤ 勞力上限。訊息「第 W 週來源 #S …」。
5. `LatestSharedHarvest()` 改讀帳；另留 `internal RecomputeLatestSharedHarvest()` 供冒煙比對；冒煙印 `SourceLedger=1`。
6. 存檔版本＋1。

**驗收：** 三個共享情境 × 種子 1～5 跑 2 年每源守恆、帳與重算逐筆相同；本節前後聚落帳逐欄相同（只加帳）；反例（採收 +100、份額 +100 未採 −100、預算 +100、份額給範圍外聚落、刪來源）在不跑重播下全被拒；存讀續跑一致；Godot `WORLD_SIM_FORAGING_OK … SourceLedger=1`。

**不做：** 依成年勞力比例分配、未採累積、取水（第 06 章）。
