# 09-1e｜畫面效能第一輪：監看值與五項小修（分支章節）

> 使用者 2026-11-16：照畫面程式的效能分析報告，依「預估效益／改動風險」的順序開始改。
>
> 接續 09-1。只改畫面與輸入處理，世界規則、推進順序、存檔都不變。每項一張 PR（很小的可兩項合一張）。

## 1｜先加監看值（之後每項都能對照）

Godot 內建的效能分析看不到 C# 函式，所以自己記（`godot/Scripts/PerfMonitors.cs`）。
執行遊戲後，在編輯器下方「除錯器 → 監看」分頁的 `world_sim` 群組：

| 監看值 | 意思 | 主要對照哪一項 |
|---|---|---|
| `map_draw_ms_max` | 地圖重畫一次的毫秒（最近一秒內最慢的一幀） | 第 4、5、6 節，下一輪的版面繪製清單 |
| `surface_update_ms_max` | 地表資料更新的毫秒（同上取最慢） | 第 2 節 |
| `bake_ms_max`、`bake_chunks_per_sec` | 一幀裡烤地表的毫秒（取最慢）、一秒烤幾塊 | 拖曳、縮放 |
| `alloc_kb_per_frame` | 平均每幀配置多少 KB 記憶體 | 第 5 節，下一輪 |
| `gc_gen0_per_sec`、`gc_gen2_per_sec` | 一秒內記憶體回收幾次（第 2 代回收會停頓比較久） | 下一輪 |

- 監看分頁大約每秒取樣一次，單幀的尖峰會漏掉，所以時間給「一秒內最慢的一幀」、次數給「一秒合計」。
- 只量測，不影響畫面與世界。CI 的 `WORLD_SIM_PERF`（09-1 第 3 節）照舊。

## 2｜地表材質表只重算變動範圍

- 原本：任何一格變動（伐木、開墾、天災強度跨階），就把全部方格的地面材質與格點重算一遍（巨大地圖 288 萬方格），在主執行緒。
- 改成：只重算變動格與四周一格的方格與格點，與「參差」（`BuildPaint`）的範圍一致；變動太多時照舊整張重算。
- 結果必須與整張重算完全相同；CI 效能量測多印 `MaterialsOk=1`（增量更新後與整張重算逐格比對）。
- 對照：`surface_update_ms_max`、CI 的 `WeekSurfaceMs`。

## 3｜滾輪與中鍵不等模擬

- 原本：快轉時任何滑鼠按鍵都先等背景這一批算完（最多約一次週結算）。滾輪縮放、中鍵拖曳也被算進去，每滾一格就停一下。
- 改成：滑鼠在地圖上時，滾輪與中鍵只動鏡頭，不等；左鍵、右鍵、鍵盤、觸控照舊等（這些才可能查詢或改變世界）。
- 滑鼠在面板上時的滾輪照舊等：事件篩選的數字框會跟著滾輪改值、重新查世界。
- 對照：快轉中連續滾輪，看編輯器「監看 → 時間 → 處理」有沒有尖峰。

## 4｜沒有動畫時不重畫

- 原本：只要世界上有遷徙隊伍，地圖每 66 毫秒整張重畫一次（暫停時也是）。隊伍已經是不會走的旗符，位置只在世界推進時變。
- 改成：畫面內有會動的東西才限速重畫——篝火、風車、水車、戰線（行軍虛線、軍旗），以及原本就有的火、天災過程、戰鬥、區域層的棋子。
- 暫停時篝火、風車照常動；畫面上沒有會動的東西時，暫停就完全不重畫。
- 原本靠持續重畫順便完成的事另外補上：紙地圖延後的補畫（最遠一層每 0.25 秒最多重畫一次）。
- 對照：暫停、不動滑鼠、畫面裡沒有聚落時，`map_draw_ms_max` 應該是 0。

## 5｜素材的寬、高、密度只問一次

- 原本：每畫一張素材都向引擎問寬、高與檔案路徑（路徑每次回傳一個新字串），畫面上幾百張素材就是每幀上千次。
- 改成：每張貼圖第一次用到時記下寬、高與像素密度，之後直接用。
- 對照：`alloc_kb_per_frame`、`map_draw_ms_max`。
